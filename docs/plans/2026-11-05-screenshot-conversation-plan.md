## 2. 实施顺序

依赖：T1 → T2；T3 → T4；T2 + T4 → T5；T2 + T5 → T6；全部完成 → T7。可以分别准备互不依赖的逻辑，但不应提前接入没有生命周期保护的自动发送入口。

### T1：队列与任务纯逻辑

预计新增：Sources/HowlerCore/ConversationQueue.swift、ConversationTask.swift，以及对应 Tests/HowlerCoreTests 测试文件。具体命名可以按实现调整。

步骤：

1. 建模自动介绍、用户问题、目标截图 ID、语言与任务状态；区分等待任务和已进入正文的消息。
2. 提供入队、开始、完成生成、完成显示、停止、失败、重试、跳过、撤回、清空事件。
3. 固定提交内容与图片关联；在任务开始时构造有效前文。
4. 明确重试不重复用户轮、不把自身部分回答作为前文；跳过保留不完整内容。
5. 为会话与请求分配代次，失效事件不可继续推进队列。

验证：合成图片/文本任务，覆盖介绍加两个追问的 FIFO、多图交错、撤回重提、失败暂停、空响应、重试替换、停止后继续、清空后迟到完成。所有测试不联网。

完成标准：队列能独立验证顺序与取消，不依赖 AppKit 或视图刷新。

### T2：接入流式执行与书写状态

修改：ChatViewModel.swift、Quill.swift；必要时调整 HowlerCore/ChatMessage.swift。新增/扩展 Tests/HowlerAppTests/StateSafetyTests.swift 及队列集成测试。

步骤：

1. send() 改为提交任务；移除生成期间拒收问题的限制，保留空输入和组字保护。
2. 串行启动 ChatClient 请求；输入、任务队列、当前输出分别管理。
3. 网络完成后等待当前书写完成，再推进；隐藏状态完成当前显示，不依赖动画回调。
4. 截图、请求、重试回调均核对代次。每次回调只能修改所属任务。
5. 实现停止/错误暂停、重试、跳过继续；防止双击产生两条相同的在途请求。
6. 服务或凭据变更时停止并暂停，用户继续后重新取当前凭据，不将 Key 放进任务。

验证：用可控 AsyncThrowingStream 分别控制“还在思考”“部分输出”“网络结束但书写未完”；检查新输入保留、最多一个请求、严格显示顺序、隐藏后继续、焚烧后旧 token 不回流。验证跨服务变更不会自动发送排队内容。

完成标准：生成速度、用户输入和显示速度互不破坏；所有退出路径都可预测。

### T3：分离窗口可见性与会话结束

修改：PanelController.swift、AppDelegate.swift；扩展应用生命周期测试。

步骤：

1. 拆分显示/聚焦、暂时收起、主动焚烧方法，移除失焦和透明边缘的销毁调用。
2. 普通快捷键在已聚焦时收起，否则显示/聚焦；菜单打开只执行打开。
3. 设置、反馈、更新检查仅收起；实际退出及更新重启释放内存。
4. Esc 先尊重输入法、截图、菜单和预览，最后处理主信纸；不拦截其他应用 Esc。
5. 焚烧立即清空业务状态，动画持有有限视觉快照；快速重新打开不受旧动画回调影响。
6. 向会话层通知隐藏状态，供 T2 决定书写完成边界。

验证：失焦、阴影点击、设置返回、快速收起/唤回、烧掉后立即再开、旧截图回调到达新会话；保留现有输入法和 Reduce Motion 回归测试。

完成标准：只有火焰按钮和信纸有效 Esc 是主动焚烧入口，隐藏不丢内容。

### T4：截图入口、偏好与语言请求

修改：HotKeyCombo.swift、HotKey.swift、HotKeyRecorder.swift、AppSettings.swift、SettingsView.swift、AppDelegate.swift、ScreenCapture.swift、PanelController.swift、SystemPrompt.swift；必要时扩展 RequestBuilder.swift。新增语言策略纯逻辑文件及测试。

步骤：

1. 新增默认 ⌥⇧H 的可配置“截图并解释”，与普通快捷键独立存储、重置和显示注册状态。
2. 校验与普通快捷键、设置快捷键、系统保留组合的冲突；录制期间暂停相关注册，结束后恢复。保留全部旧快捷键迁移。
3. 截图入口可从没有信纸的状态启动；记录此前可见状态，取消恢复，重复触发去重。
4. 回调成功后创建图片引用与自动介绍任务；处理权限不足、不可读图片、未配置服务和缺 Key，不自动循环重试。
5. 新增跟随系统/指定回答语言，解析稳定语言标识；无偏好时自动迁移为跟随系统。
6. 为自动介绍和普通问题构造语言指令；保留原用户文字用于展示，通过请求上下文传递指令。
7. 清空系统提示词时继续不发送 system/date；保留自定义系统提示词和 body 覆盖契约。配置检查应覆盖实际使用的任务指令，语言变更使相关检查结果失效。

验证：快捷键配置编解码、冲突与迁移、系统语言解析/回退/简繁、已排队语言不漂移；三种协议的语言和图片请求形状、system 关闭、body 覆盖，以及敏感字段不出现在日志。截图成功恰好产生一个任务，取消不发请求。

完成标准：无需额外按键即可入队解释；普通粘贴行为未变；不发送多余系统个人信息。

### T5：信纸交互与多图关联

修改：HowlerView.swift、Transcript.swift、Seals.swift、DemoMode.swift；必要时拆出小型视图。

步骤：

1. 输入框始终可用，旁边标明草稿关联图片；等待区显示顺序、摘要、目标图和可撤回状态。
2. 保留并展示已发送截图预览。新截图不替换旧任务，已有草稿不静默换图。
3. 正文中的自动介绍使用简短标签；每个问题轮到执行才进入正文。
4. 增加停止、重试、跳过继续的明确状态；失败处保留可读上下文。
5. 去掉自动推进引起的强制滚动，保留阅读位置和选区复制，完成时不抢焦点。
6. 添加右上角火焰入口，与附件印章错开；设置点击范围、键盘导航、读屏名称与悬停提示。
7. 更新页脚快捷键说明。增加合成演示状态：介绍中排队、两图关联、失败暂停、隐藏恢复。

验证：无需真实 Key 的演示与截图；浅色/深色、Reduce Motion、长问题、长队列、小屏幕、键盘操作、输入法、VoiceOver。确认等待区与火焰入口不遮挡附件和输入。

完成标准：视觉上区分当前回答、等待问题和草稿；用户能理解“停止”和“焚烧”的区别。

### T6：故障与资源生命周期回归

修改：前述相关文件与测试；不引入独立持久化会话存储。

步骤：

1. 检查图片在正文、队列、预览间的引用，清空时统一释放，不无意义复制图片数据。
2. 检查临时文件的成功、取消、读失败和过期回调路径；维持尝试删除语义。
3. 覆盖服务变更、凭据失败、模型不支持图片、空流、断流、重试和跳过。
4. 用快速交错事件测试截图/取消/失焦/隐藏/焚烧/重新打开；不得丢草稿或恢复旧内容。
5. 确认 UserDefaults 仅增加语言/快捷键；请求仍使用 ephemeral 会话，Key 仍在 Keychain，无新遥测。

完成标准：错误可恢复，旧结果不越过会话边界，隐藏状态不导致队列死等动画。

### T7：文档、真实验证与交付

修改：README.md、README.zh-CN.md、ACCEPTANCE.md；实际实现改变既有工程契约时同步 AGENTS.md。保留本计划为目标说明，不把未完成项写成已经支持。

步骤：

1. 更新自动截图发送、语言偏好、停止/队列、快捷键和火焰入口说明。
2. 两份 README 明确“收起保留内存，焚烧清空”，更新新增持久化偏好和语言传输说明。
3. 替换 ACCEPTANCE.md 中“外部点击烧掉”“重复快捷键烧掉”“设置打开清空”等旧行为，增加下表用例。
4. 运行 `make test`；进入 PR 验证阶段后执行本地签名环境支持的 `make app`。签名身份仅从环境读取，不写入文档。
5. 在获得安装/替换应用授权后，用相同 Developer ID 的应用完成真实环境检查；需要服务凭据时使用现有安全配置流程，不在对话或测试中记录 Key。
6. 检查真实图片解释与语言质量。提供合成内容截图，人工确认交互与视觉效果；自动测试通过不等于模型质量或用户验收通过。
7. 按仓库协作规则安排独立 diff 和公开内容审查。提交、推送、PR、安装和发布均遵循后续任务明确授权，本计划不自行授权执行。

完成标准：源代码、测试、真实环境、模型表现与人工验收分别记录结果和未验证项；没有未解释的关键失败。

## 3. 验收矩阵

以下全部为待执行用例，不是测试结果。只使用合成文字和图片；实际版本、环境及结果在实施时记录，不提交用户内容或个人签名信息。

| 场景 | 预期 | 证据类型 |
| --- | --- | --- |
| 独立截图成功 | 自动介绍，无额外回车，恰好一条请求 | 应用集成 + 真实操作 |
| 介绍思考期间提交 Q1/Q2 | 介绍、Q1 答复、Q2 答复依次完成 | 可控流 + 人工 |
| 网络结束但羽毛笔未写完 | 下一段不抢先；减少动态效果立即完成显示 | 集成 + 演示 |
| 收起期间网络完成 | 队列继续，唤回顺序正确，无积压动画 | 集成 + 真实操作 |
| 英文截图，中文偏好 | 中文解释，必要英文原文可核对 | 请求测试 + 真实模型 |
| 用户明确要求另一语言 | 当前轮按要求，其他排队项保持原语言 | 请求测试 + 真实模型 |
| system 关闭或 body 自定义 | 保留兼容契约，语言行为如实验证 | 三协议测试 + 真实模型 |
| Q1 失败后已有 Q2 | Q2 暂停；重试无重复，跳过需显式操作 | 可控流 |
| 图一草稿存在时捕获图二 | 旧草稿仍指图一，新图介绍正常排队 | 单元 + 人工 |
| 截图取消/权限不足/重复触发 | 不发送、不丢内容、不出现多个选择器 | 集成 + 真实操作 |
| 点击外部/阴影、打开设置 | 保留内容与队列，不抢焦点 | 真实操作 |
| 普通快捷键/菜单打开 | 收起与唤回规则一致，菜单不反向关闭 | 真实操作 |
| 输入法组字、菜单、预览、框选中的 Esc | 先取消局部交互，不误烧 | 人工 |
| 火焰/Esc 焚烧后旧回调到达 | 新会话无旧文本、图片或队列 | 竞态测试 |
| 服务来源或 Key 改动 | 停止并暂停，无静默跨服务发送 | 集成 |
| 无图能力、模糊小字、图表、报错 | 能解释则可核对，不能则明确说明 | 真实模型 + 人工判断 |
| 深浅色、小屏幕、多显示器、全屏应用 | 可读、可操作、正确屏幕定位 | 真实操作 + 截图 |
| Reduce Motion、VoiceOver、选区复制 | 无多余动画，控件可识别，复制不回归 | 自动回归 + 人工 |
| 焚烧/退出后的数据检查 | 不持久化对话；临时文件清理结果如实记录 | 源码 + 集成 |

## 4. 发布边界与暂缓项

本次设计和实施计划不指定发布日期、版本号或真实服务质量承诺。版本保持仓库要求的 0.1.x；未来发布时再独立递增 VERSION/BUILD_NUMBER，编写对应版本发布说明并遵循 CI 发布流程。

区域标注、答案定位高亮、两图比较在本期完成并获得真实使用反馈后再评估。图形化模型配置等其他上手改善不混入本次实现。

设计中的新增默认快捷键、队列模型名称及文件拆分属于可逆工程选择；若真实验证发现冲突，可调整并同步文档。自动解释、严格顺序、用户语言、仅两种主动焚烧入口属于本期产品契约，不能在实施中悄悄降级。
