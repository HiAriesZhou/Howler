# 截图自动解释与顺序答疑：设计

日期：2026-11-05。状态：产品方案已确认，实施中。

配套文档：[实施计划](2026-11-05-screenshot-conversation-plan.md)。本文描述目标行为；当前版本用法仍以两份 README 为准。

## 1. 定位与范围

Howler 面向需要临时解释概念、翻译文字和理解截图的 macOS 用户。长期目标是成为一小群用户持续使用、愿意推荐的开源工具。保留信纸、羽毛笔和阅后即焚的特点，优先改善日常使用，再深化截图理解。

本期核心体验：**截完就开始解释；想到问题随时写；回答依次展开；由用户决定什么时候烧掉。**

纳入本期：

- 独立的“截图并解释”快捷键；框选成功后自动发送。
- 介绍期间可以编辑和提交追问；介绍和答疑严格按序呈现。
- 用户回答语言偏好，不受截图语言影响。
- 失焦保留、暂时收起与主动焚烧的独立语义。
- 右下角火焰关闭入口；Esc 的分层处理。设置与菜单按 [2026-11-06 修订](2026-11-06-settings-refinement.md) 分为三个标签页，并增加截图解释开关。
- 同一封信内继续截图，各问题明确关联截图。
- 失败、取消、重试、服务配置变动和迟到回调的处理。

不纳入本期：区域标注、答案定位高亮、专门的两图比较、整屏翻译覆盖层、历史记录、后台读屏、自动操作其他应用、联网搜索。未来候选功能须以实际使用需求为依据。

## 2. 截图入口与默认介绍

普通快捷键继续服务文字问答；新增独立、可配置的截图快捷键。实施默认值采用 ⌥⇧H，保留普通快捷键及其既有迁移规则。如果新组合与已有配置或其他应用冲突，保留原快捷键，新入口显示冲突并允许重设，不抢占。

入口明确命名为“截图并解释”，说明框选结束即发送至已配置的模型。成功框选后自动展示信纸并加入介绍任务，不增加每次发送确认。首次录屏权限仍由系统处理；权限未授予不截图、不发送，授权后由用户重新触发。

框选前暂时隐藏信纸，避免截入 Howler；取消框选不产生请求，恢复此前的内容、草稿、窗口可见状态和焦点安排。未打开信纸时取消，不留下空白窗口。框选期间重复触发只保留一个选择器。

默认介绍先概括，再给少量重要信息：

| 内容 | 介绍目标 |
| --- | --- |
| 文章、外语文字 | 主要意思、必要的术语；需要时引用短原文 |
| 界面、报错 | 可见状态、关键提示；明确区分事实与推测 |
| 图表 | 比较对象、主要趋势、重要标注；不编造读不清的数值 |
| 普通图片 | 主体和明显细节 |

不默认逐字翻译整张图，不强制固定字数。模糊、缺少上下文或模型不支持图片时给出可理解的说明；不得假装读图成功。截图预览在提交后仍可查看，不能随待发送附件清空而消失。

截图菜单项与快捷键采用同样的自动解释行为，并更新名称。粘贴图片、粘贴文字仍先成为附件，由用户发送，避免把粘贴变成意外网络请求。

## 3. 会话与队列

### 3.1 输入和呈现

输入框在思考、流式输出和羽毛笔显示期间始终可编辑。回车提交一个任务，清空这份草稿；未按回车的文字不发送。保持输入法组合文本与现有换行行为。

等待项位于输入框附近，显示问题摘要、目标图片和状态。未开始的问题可撤回到草稿修改；撤回不覆盖已有草稿，草稿非空时先处理当前草稿。重新提交加入队尾，不暗中合并或重排。

正文顺序为“图片介绍 → 问题一与回答 → 问题二与回答”。等待项不提前混入介绍正文，内部生成的自动提问不伪装成用户手动输入。介绍使用简短的“图片介绍”标签。

队列推进不强制滚动；用户位于底部时随正文显示跟随，向上阅读时保留位置。后台完成不抢焦点、不突然置顶。手动发送与自动推进应分别处理，避免现有消息数量变化逻辑强制跳到底部。

### 3.2 执行与显示边界

采用严格串行执行，每次最多一个模型请求。任务开始时使用此前已完成或被用户明确保留的部分回答作为上下文；未开始的任务不提前加入请求历史。

每项有 queued、generating、revealing、completed、paused/failed 或 skipped 状态。网络结束与羽毛笔显示结束是两个事件：前一项完成生成且完整呈现后，才开始下一项。首期用这个简单边界保证顺序；后续如需预取，应另行验证，不能让新回答提前出现。

减少动态效果下，revealing 随已收到文字立即完成，不增加人为等待。收起窗口后不依赖屏幕刷新推进队列：网络完成时将该段视为已显示完成，后台按序处理；再次打开呈现已有正文，不重播积压书写动画。

### 3.3 多张截图和草稿归属

第二次截图形成新的介绍任务，加入队尾，不替换原图或取消现有输出。例如：图一介绍 → 关于图一的问题 → 图二介绍 → 关于图二的问题。

每个截图有稳定标识；任务提交时固定目标截图、问题文字与回答语言。后来的截图不能改变已排队任务。相关图片通过历史或显式附件传递，避免同一图片在一次请求中无意义地重复编码。

新截图成功后，空白输入框默认面向新图。已有非空草稿仍关联原图，输入框旁明确显示图片编号/缩略图；草稿发送或丢弃后才默认切到最新图。用户可显式切换草稿目标。首次截图前的纯文字草稿保留为无图片关联，不能被自动介绍吞掉。

等待中的截图介绍首期不提供单独删除，避免留下无图的追问；可以暂停并跳过介绍，原图仍保留给后续问题。图片只在本次会话存活，不引入图库。

### 3.4 停止、失败与重试

| 事件 | 当前项 | 后续任务 |
| --- | --- | --- |
| 用户停止 | 取消请求、保留部分内容、结束书写动画 | 暂停，等待用户选择 |
| 网络或模型错误 | 原位置显示错误，保留图片和部分内容 | 暂停，不自动跳过 |
| 重试当前项 | 以相同用户输入/图片重试；旧的部分答案被替换，不作为自身上下文 | 原顺序不变 |
| 跳过并继续 | 保留部分内容并标记“不完整”；若无内容则仅保留失败/跳过状态 | 使用有效前文继续 |
| 焚烧 | 立即取消并失效当前请求 | 全部清空 |

不自动无限重试。错误信息沿用凭据遮盖规则。空响应也应成为可恢复错误，不能被当作正常介绍。

任务携带会话代次及请求标识；停止、重试、焚烧和退出后到达的旧结果不得写入当前项或新信纸。截图回调也受同一会话失效检查约束，临时文件在成功、取消和读取失败路径均尝试清理。

模型服务来源、模型、凭据或请求格式在会话中改变时，取消当前生成并暂停队列，保留内容并提示变更；用户显式重试或继续才使用新配置。不得把旧任务悄悄发送至新服务，也不能在队列中保存凭据副本。仅回答语言或系统指令变动不取消当前请求，作用于之后提交的任务。

## 4. 回答语言

设置新增“回答语言：跟随系统／指定语言”。跟随系统读取 macOS 首选语言，保留简繁等必要语言信息；无法解析时回退英文。不通过截图文字、当前输入法或 Howler 尚未本地化的界面语言猜测。

优先级：当前问题明确要求的语言 > 指定回答语言 > 系统首选语言。当前问题的语言覆盖不修改持久化设置，也不改变已排队任务。回答语言在提交时解析为稳定值，队列执行中不漂移。

服务请求只传必要的回答语言指令，不传完整系统语言列表、地区、用户身份或时区。图中文字属于待解释内容，不能覆盖用户语言偏好。

现有自定义系统指令与服务请求 body 覆盖保持兼容。语言要求通过当前请求的任务指令传达，不用恢复被用户关闭的 system 消息来实现；清空系统指令仍关闭系统提示词及日期。保存的自定义指令不自动改写。系统指令与任务指令冲突时模型遵循效果需要真实服务验证，不能宣称提示词必然保证输出语言。

## 5. 窗口、焦点与焚烧

| 操作 | 目标行为 |
| --- | --- |
| 点击信纸外部或阴影、切换应用 | 交出焦点；信纸可见、内容保留、生成继续 |
| 信纸隐藏或未聚焦时按普通快捷键 | 显示并聚焦原信纸；没有会话则创建 |
| 信纸已聚焦时再按普通快捷键 | 暂时收起，内容和队列保留 |
| 菜单选择打开 | 只显示/聚焦，不反向收起 |
| 打开设置、反馈或更新界面 | 可暂时收起信纸；不清空会话 |
| 右下角火焰按钮 | 焚烧，取消所有任务并清空会话 |
| 信纸正常交互状态下 Esc | 同火焰按钮 |
| 退出、实际更新重启 | 内存会话结束；重启不恢复 |

Esc 优先交给正在发生的局部交互：截图选择器、输入法组字、菜单、预览等；这些交互结束后，信纸获得焦点时的 Esc 才焚烧。在其他应用里按 Esc 不影响 Howler。

清空业务状态在焚烧开始时完成，动画只使用必要的视觉快照，不让旧正文模型继续存活并接受回调。动画结束释放快照。燃烧中再次呼出得到全新空白会话，旧动画结束事件不得关闭新窗口。

暂时收起不是会话结束；仍只保存在内存，可能直到用户主动焚烧或退出才释放。两份 README 的“关闭即清空”描述必须改为明确区分收起与焚烧。

## 6. 视觉和无障碍

右下角设置独立的小火焰印记，与从底部开始的燃烧方向一致；固定在信纸边角，不随正文滚动，页脚为它留出空间。平时静止、清楚可辨，悬停轻微亮起，提示“焚烧此信 · Esc”。单击直接执行，不增加确认弹窗。

外观沿用现有纸张、墨色、火漆和燃烧材质，不新增复杂工具栏。关闭入口应有足够点击面积、键盘焦点和“关闭并清空对话”的读屏名称，浅色/深色模式均可辨识。截图关联、排队和错误不能仅靠颜色表达。

保留选区复制、输入法、阅读位置和 Reduce Motion。待答区域紧凑，列表过长时独立滚动，不把信纸无限撑长。生成期间不能重建输入框导致光标或组合文本丢失。

## 7. 结构与数据流

数据流：显式框选 → 本地准备图片 → 入队截图介绍 → 串行模型请求 → 按序书写 → 追问任务 → 主动焚烧并清空。

| 层 | 职责与预计文件 |
| --- | --- |
| HowlerCore | 新的队列状态与任务模型、图片关联、语言策略、自动介绍请求；保持纯逻辑可测 |
| 应用会话 | ChatViewModel.swift 协调队列、流式请求、羽毛笔、取消代次；不把生成状态等同于输入可用性 |
| 窗口/截图 | PanelController.swift、ScreenCapture.swift、AppDelegate.swift 分离 show/focus/conceal/burn/capture 生命周期 |
| 视图 | HowlerView.swift、Transcript.swift、Seals.swift 展示等待项、持久预览、火焰入口和顺序正文 |
| 偏好 | AppSettings.swift、SettingsView.swift、HotKeyCombo.swift、HotKeyRecorder.swift 保存语言与独立截图快捷键 |

现有一次会话内单附件的消息编码可作为基础；扩展应用层图片标识，不必先重写三种服务协议。RequestBuilder、ChatClient 与语言/介绍指令的集成必须覆盖三种格式。

## 8. 隐私和验收边界

保持 Keychain、临时截图文件清理、ephemeral 网络会话和无遥测。仅用户框选或粘贴才读取对应内容。新增持久化项仅为回答语言和截图快捷键；草稿、图片、队列及会话不持久化。

“阅后即焚”指 Howler 本地数据生命周期，不承诺删除模型服务端的数据。自动截图发送、隐藏仍保留内存、语言指令属于用户可理解的行为，应在用法与隐私说明中准确表述。

验收包括纯逻辑测试、可控流式测试、签名应用真实操作、真实模型看图与语言验证、用户体验确认。这些证据分别记录；本设计文档不表示任一实现检查已通过。详细用例及执行顺序见实施计划。
